# v0.8.36 Release Notes

## Generic Context Compatibility Evidence

This release adds a version-neutral Context compatibility manifest and runner
for the installed package boundary. The package smoke derives the manifest from
the exact materialized tarball and verifies its package name, version, SHA-256,
content identity, required public paths, and source-fallback policy before it
executes any Context command.

The installed CLI scenarios cover default status, safe preview and explain,
preview-only initialization, explicit enable with no-overwrite behavior, and
invalid configuration. The runner returns fixed result codes and removes its
temporary scenario state after every run.

## Safety And Scope Boundaries

- Malformed manifests, missing subjects, archive digest or content-identity
  mismatches, unavailable package paths, and source-linked installed files stop
  before a Context command can run.
- The package check uses a fresh isolated installation and rejects any source
  fallback, including an executable path that resolves into the source tree.
- Context remains explicit opt-in and default-off. This release adds no new
  public Context command, OpenCode host delivery, runtime injection default,
  workflow, evidence, authority, network, process, or personal-store behavior.
- The package materialization test uses the repository's shared pack lock, so
  concurrent test workers cannot create a partial tarball during verification.

## Verification

The release path verifies manifest parsing and fail-closed diagnostics, a fresh
tarball installation, all declared installed CLI scenarios, source-fallback
rejection, package smoke, type safety, full repository Vitest, documentation,
scope, release workflow, protected CI, canonical tar identity, and registry
provenance.

## Source Preparation Boundary

source-preparation candidate. It makes no npm package, Git tag, dist-tag

## Canonical Tar Publisher Handoff

The packaged
[`consumer-authority-beta18-acceptance.json`](consumer-authority-beta18-acceptance.json)
records the two-runtime release boundary:

1. Node `20.19.0` with npm `10.8.2` creates one normalized canonical tarball
   and package facts under isolated npm and Git configuration.
2. Node `24.18.0` with npm `11.16.0` receives only that exact tarball and its
   facts in a distinct isolated npm home/cache/configuration. It rejects a
   workspace publish, mismatched tarball/facts, a wrong runtime, or inherited
   packer configuration. This publisher exceeds npm Trusted Publishing's Node
   `22.14.0` and npm `11.5.1` runtime floor.
3. The publisher runs the exact canonical-tar npm publish argv once with
   `--dry-run`, then the hosted workflow alone may issue the matching real
   registry PUT without repacking.

The handoff does not add a token fallback, custom OIDC exchange, or printed
authentication state. npm Trusted Publishing remains the authentication route.
The manual release workflow exercises the same canonical-tar Node24 dry-run
route so it cannot validate a different workspace-publish command.

The current package retains the previous bounded observer contracts:
`preflight-consumer-authority-observer.mjs`,
`preflight-consumer-authority-external-attestation.mjs`, and
`preflight-consumer-authority-external-artifact-transport.mjs`. They remain
no-token/no-artifact preparation only; the publisher handoff neither replaces
their privacy boundaries nor grants consumer authority.

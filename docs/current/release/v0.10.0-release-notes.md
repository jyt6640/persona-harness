# v0.10.0 Release Notes

## Default-Safe `(PH)` Routing

OpenCode's compact shared-skill advisory route is now controlled by the new
`features.sharedSkillRouting` configuration. It defaults on for a safe Persona
Harness configuration and is independent from the legacy
`features.runtimeInjection` setting, which remains default-off.

The route still selects at most one compact catalog reference and asks the
assistant to begin its response with a bounded `(PH) <skill>` notice. It does
not load the full skill body, inject rule/profile context, run commands, or
advance a workflow.

## Safe First-Run Proposal

When an installed OpenCode integration receives a relevant Persona request in a
project without `.persona`, it now offers one `(PH) Setup` recommendation
instead of starting an interview or another workflow skill. The recommendation
is advisory and leaves the project unchanged. Only a later clear user
acceptance may authorize the existing `npx ph init` command, which creates only
its manifest-owned Persona configuration and host adapters. It does not imply
`bootstrap`, `attach`, workflow, Git, or network work.

Only that managed initialization enables automatic routing. A Context-only or
partial `.persona` directory stays outside shared-skill routing, so it cannot
silently start an interview or workflow route.

## Configuration And Diagnosis

`ph init` preserves an explicit `features.sharedSkillRouting: false` during a
managed update. `ph doctor` separately reports the local routing configuration,
native catalog readiness, and the still-unobserved host selection and delivery
facts.

## Boundaries Preserved

- This package does not claim that a live OpenCode session selected or followed
  a skill. Live host selection and delivery remain separate observation
  boundaries.
- Legacy runtime context injection remains default-off, and Context remains
  explicit and default-off.
- The first-run proposal itself does not create `.persona`, change host
  configuration, execute a shell command, or create workflow, evidence,
  authority, or external state.

## Verification

The release path verifies configuration default/opt-out behavior, first-run
proposal and explicit-acceptance boundaries, compact route notices, generated
adapter metadata, TypeScript type safety, the canonical packed package,
protected CI, and registry provenance.

# v0.9.0 Release Notes

## Portable Host Capability Foundation

Persona Harness now derives assurance from a versioned host capability
manifest instead of assuming that every host exposes the same controls. The
public package models Codex, OpenCode, Claude Code, and Antigravity through one
host-neutral contract.

Each manifest declares finite support states for skill discovery, input
routing, philosophy injection, activation notices, pre-tool gates, completion
gates, session persistence, and adapter updates. The current OpenCode path uses
an explicit compatibility manifest rather than an implicit all-capabilities
default.

## Assurance And Failure Boundaries

- Default policy reports portable assurance when the required cross-host
  behavior is available but enforcement controls are not.
- Projects that require enforced assurance fail closed when a required
  enforcement capability is unavailable.
- Unknown hosts, schemas, capabilities, states, duplicate capabilities, and
  incompatible host or adapter versions fail closed with bounded diagnostics.
- Raw manifest input is not reflected in public failure results.

## Portable Skill Materialization

`ph init` materializes each canonical Persona Harness skill as a regular,
manifest-owned project adapter for Codex and Antigravity (`.agents/skills`),
Claude Code (`.claude/skills`), and OpenCode (`.opencode/skills`). Generated
paths are no-follow checked; modified, user-owned, or symlinked adapters fail
closed instead of being overwritten. The OpenCode plugin leaves host skill
settings unchanged so only the project-local OpenCode adapter is eligible for
its automatic discovery path.

## Scope

This release establishes the 0.9 host-neutral foundation and portable static
skill materialization. Automatic adapter updates and real-host launch
integration remain separately governed follow-up work and are not claimed by
this slice.

## Verification

The release path verifies focused manifest and negotiation contracts,
TypeScript type safety, repository tests, documentation and release policy,
canonical package identity, an isolated installed package with
`sourceFallback=false`, protected CI, and registry provenance.

## Builder Reliability

The canonical clean CI builder keeps its five-minute default command budget.
Its serial resource-sensitive Gradle and fixture test command has a separately
declared seven-minute ceiling, which remains bounded and is included in the
fixed builder command configuration. Timeout, output-limit, and process-lifecycle
failures remain fail-closed.

# v1.0.0 Release Notes

## Authorization-Aware Engineering Guidance

Persona Harness 1.0.0 aligns its portable skill guidance with current coding
models, including GPT-6 Astra. Generated Codex, Claude Code, OpenCode, and
Antigravity adapters share instructions to carry authorized work through
implementation and appropriate verification, reuse approval within its scope,
and treat status questions and corrections as steering of the active task.

Clarification is handled before another interview question. Explicit stop and
cancel requests take effect immediately. A procedural skill handoff does not
create a new approval checkpoint for work the user already authorized.

## Philosophy And Evidence

Project conventions and approved decisions remain the source for relevant
engineering context. Skill selection grants no new permission, and the existing
workflow, authority, ownership, and fail-closed checks remain in place. The
legacy runtime injection and Context opt-in boundaries are unchanged.

The OpenCode system guidance no longer requires a new implementation request
and an accepted workflow plan for every small edit or status follow-up. A
blocked Finish still prevents a completion claim, while diagnosis and in-scope
correction can continue under the existing authorization.

## Migration

This is a major version transition. Existing automatic updates must retain
their major-version approval, active-session pinning, and user-customization
preservation rules. The host owns model selection and API requests; Persona
Harness does not silently change provider, sampling, reasoning, or credentials.

The packaged [Korean migration guide](../astra-migration-guide.ko.md) covers
Codex settings, task prompts, AGENTS.md organization, and observable scenarios.

## Verification Scope

Behavioral checks retain routing, cancellation, approval, injection opt-out,
and adapter ownership coverage. Canonical generated assets and installed CLI
checks prove package delivery. Live four-host behavior, independent-user
outcomes, and token or quality improvements require their own observations.
The release does not claim these from prompt changes or synthetic tests.

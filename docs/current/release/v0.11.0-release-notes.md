# v0.11.0 Release Notes

## Portable Codex And Claude Code Plugins

Persona Harness now ships the canonical shared-skill catalog as versioned,
package-contained plugin artifacts for Codex and Claude Code. The artifacts
contain the same bounded `(PH)` skill references used by the existing portable
adapter materialization path.

Use the read-only command below to locate a verified installed artifact:

```bash
npx ph plugin path codex
npx ph plugin path claude
```

The command validates the package-owned manifests and every catalog skill
before it prints a path. Missing, duplicate, stale, modified, or symlinked
artifacts fail closed.

## Explicit Host Ownership

Persona Harness does not register a Codex marketplace, install or enable a
plugin, alter Claude Code configuration, or claim live host selection. Those
are intentional user- or host-owned actions. The package documents the normal
Codex marketplace and Claude plugin-directory commands after the verified path
is available.

## Compatibility

- The Codex artifact uses the supported `.agents/plugins/marketplace.json`
  marketplace layout.
- The Claude Code artifact uses a baseline plugin manifest accepted by the
  installed Claude Code validator; it avoids metadata that requires a newer
  host version.
- The artifact generator is byte-bound to the canonical shared-skill catalog.
  It neither enables Context nor changes the default-off runtime-injection
  boundary.

## Verification

The source and package checks cover canonical catalog-to-plugin byte bindings,
manifest identity and version binding, missing/duplicate/symlink rejection,
installed package discovery, and user-owned adapter preservation. A disposable
installed tarball was also validated through the local Codex marketplace/plugin
commands and the Claude Code plugin validator.

Registry/provenance readback remains part of the governed release workflow.
Static package validation does not prove live host skill selection, activation,
or delivery in a user session.

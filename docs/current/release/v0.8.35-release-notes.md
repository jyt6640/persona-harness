# v0.8.35 Release Notes

## Team Profile V2

This release adds a separate, repository-local Team Profile v2 source at
`.persona/team-profile.jsonc`. It accepts JSONC comments, validates the exact
`persona-context-team-profile.2` schema, and converts valid shared rules only
into an explicit team layer for the pure Context resolver.

The existing v1 profile remains at `.persona/team-profile.json`. v1 and v2 are
separate readers: a v1 document is never upgraded, copied, or silently treated
as v2.

## Safety And Scope Boundaries

- Unknown fields, unsupported versions, malformed JSONC, duplicate rule ids,
  active same-topic conflicts, oversized input, and symlinked files fail closed
  with fixed nonreflective diagnostics.
- Shared text rejects control characters, credential-shaped data, private
  absolute paths, external URLs, remote-fetch or shell/process instructions,
  authority or security-weakening instructions, and personal-profile-shaped
  content before it reaches the resolver.
- Valid v2 data is read-only and preserves the fixed resolver precedence:
  `product invariants > task > project > team > personal > language > common`.
- This release adds no CLI command, OpenCode adapter delivery, runtime default,
  workflow, evidence, authority, network, process, or personal-store behavior.

## Verification

The release path verifies v1/v2 separation, bounded nonreflective parsing,
project > team > personal precedence through a temporary project fixture,
source import boundaries, type safety, documentation, package installation,
protected CI, canonical tar identity, and registry provenance.

# v0.8.29 Release Notes

## Clearer project guidance in OpenCode

A ready project profile can provide one compact, safe `philosophy.project`
convention automatically to the OpenCode system context. This narrow project
guidance defaults on without enabling broader runtime injection, workflow
automation, personal philosophy refinement, or completion authority.

The OpenCode plugin also registers Persona Harness's bundled shared-skill
directory with the host-native skill loader. Current OpenCode 1.x
`skills.paths` configuration and compatible newer `skills` source arrays retain
their existing sources. Registration makes skills discoverable; it does not
activate a skill, inject every skill body, or run workflow commands.

## More natural design conversations

OAuth design holds now explain an unanswered term instead of treating a
clarification request as an answer. A clear request to stop the interview or
switch to a non-auth workflow diagnostic clears an unapproved hold, and an
approved authentication handoff remains available for later related work in the
same session. Obvious standalone approval typos such as `approver` are
accepted, while prose and unrelated lookalikes remain blocked.

When a compact Persona skill route is selected, the next response includes a
short notice naming the skill, whether selection was automatic or explicit, and
the bounded reason in the user's language.

## Release boundary

Fresh source and package verification bind the exact `0.8.29` tar before
protected integration, immutable tagging, the stable GitHub Release, and one
npm `latest` publication. Registry and provenance readback remain the separate
completion record for that publication.
